# Xinbaopedia 内容更新模板

本文件是内容编辑的统一入口。目标是：新增论文、动态或研究内容时，只更新事实和素材，沿用已经确认的结构与展示方式，不重新设计卡片、裁剪风格、链接格式或交互。只有用户明确提出改版时才调整模板，并同步更新本文件及相关验收。

## 1. 权威来源与适用范围

| 内容 | 编辑位置 | 一致性要求 |
| --- | --- | --- |
| 论文事实、简介、TL;DR、资源链接、配图元数据 | `wiki/<Slug>.md` 与 `wiki/<Slug>_zh.md` | 两种语言表达相同事实、条件和证据边界 |
| 首页与归档动态 | `lib/site-updates.ts` | 一份有序事件数据；引用论文 slug、完整标题、已确认 PDF 及首页图 |
| 论文索引、研究分类、CV | 对应 `wiki/*.md` | 从论文事实同步；保留各页面既有用途与条目顺序 |
| 图片文件 | `public/papers/<paper-id>/` | 使用原始论文、作者提供的 Poster 或获准公开的源素材 |
| 派生知识与检索数据 | 维护器生成的文件 | 不手工编辑；流程见 [持续维护](continuous-maintenance.md) |

字段定义以 `lib/paper-highlights.ts`、`lib/site-updates.ts` 和维护 schema 为准；本文件规定如何填写内容，不另建一套数据模型。`scripts/new-wiki-page.mjs` 只是基础骨架，生成的 TODO 和未审阅元数据不代表完整论文模板。

历史任务记录不是后续排版模板。历史中的正方形缩略图、居中窄图区、按原图比例限制预览宽度等方案已经被下述当前规则取代。`docs/chat/persona-prompt.md` 管理聊天助手语气，不用于生成或维护论文页面。

## 2. 每次内容更新的固定输入

先从已有页面和资料补齐以下信息，只询问无法确认且影响内容正确性的缺项。不要重复询问已确定的样式偏好。

- 完整论文标题、稳定 slug、作者顺序、已确认中文姓名、共同一作及通讯作者标记。
- 当前状态及其证据；会议名称、年份、时间和地点分别核实，录用日期不等于会议日期。
- 公开且可使用的论文版本、Camera-Ready PDF、Poster、框架图、理论或实验图。
- 每项资源的实际 URL、类型、可访问性；已有资源不因本次未再次提供而被删除。
- 核心问题、主要发现或方法、证据范围及重要限制。

信息不足时列出具体缺项，保留已经核实的部分。不得编造录用、作者、结果、Poster、资源 URL，或用重复图片凑齐三个位置。当前录用卡片要求三张有效辅助图；素材不足时保持该卡片未就绪，向用户索取缺项，继续其他独立内容工作。

## 3. 文字模板

### 共通规则

- 第三人称、客观、简洁的学术百科语言；先说明问题和意义，再说明方法与证据。
- 标题沿用正式完整标题。不得为适应版面擅自缩写、改名或使用省略号替代。
- 数值、优越性、因果与理论保证必须有对应来源；保留适用条件、负面结果和限制。
- 不将站点维护、选图理由、内部处理过程写入公共正文。
- 中文姓名使用已确认写法，例如 **Zhuoyang Shen → 沈卓洋**；未确认姓名保留原文，不猜译。
- 研究方向标签统一使用 **Data Acquisition**；论文内具体的“数据生成”概念或正式标题仍按原意表达，不能全局替换。
- 同一事实跨语言一致，中文正文自然表达；正式英文论文标题可在两种语言中保持一致。

### 首页录用动态

标题：`“<完整论文标题>” accepted at <会议 年份>` / `《<完整论文标题>》获 <会议 年份> 录用`。同一批录用的多篇论文使用同一事件，完整列出标题，维持既定顺序。

仅有月份证据就显示年月，不编造具体日期。只记录有实质意义的学术或生涯事件；不把常规维护、补链接或代码发布当作录用动态。不要在标题和辅助文字重复“已录用”。

首页保留滚动近四年的事件，较早事件保留在归档；不显示 “Past 4 Years”。初始及关闭后重开时，内部默认仅展开最近一次**论文录用**，不是最近一条荣誉或其他动态。同批多篇沿用左右切换，标题、TL;DR、图片和链接一起切换。

### TL;DR

默认 2 句、必要时 3 句：**问题/发现 → 方法或证据 → 必要条件**。英文通常 35–65 词，中文通常 70–140 字；这是编辑目标而非压缩重要限制的硬性理由。当前完整性检查还要求每种语言的 TL;DR 至少 60 个字符。

```text
EN: <What problem or failure mode does the paper establish?>
    <What mechanism, method or evidence explains/addresses it, under what scope?>
ZH: <研究揭示或处理什么问题？><用何种机制、方法或证据说明，适用范围是什么？>
```

不要复制摘要全文、重复作者和会议信息，或加入 “Method comparison from the poster: ...” 等说明图片来源的冗余句。图号和必要来源写进 alt 或维护记录，事实来源在正文引用。

### 点击标题后的论文详情页

沿用现有 slug 和有效锚点，不为了模板整齐而无故重命名已有小节。新页面默认结构如下；无证据的小节可省略，不生成空标题。

| 顺序 | 英文 / 中文 | 内容要求 |
| --- | --- | --- |
| 导语 | 无额外小节标题 | 完整标题、作者、已证实状态；2–4 句解释研究问题及主要贡献 |
| 背景与概述 | Overview / 研究概述 | 为什么重要、与已有问题的关系；不重复导语和摘要 |
| 方法 | Method / 方法 | 高层机制和必要条件；重要公式可使用原文表达，不用公式替代解释 |
| 结果 | Results / 研究结果 | 数据、比较、理论或实验发现及其边界；区分作者报告与本站独立验证 |
| 启示（必需） | Key takeaways / 关键启示 | 通常 3–4 条可记忆、可迁移的结论，每条一项主张及必要条件 |
| 研究关联 | Placement / 研究关联 | 链接相关研究方向和论文，说明实质联系 |
| 引用 | 就近脚注或来源链接 | 每项重要主张可追溯；不得以链接数量代替证据质量 |

详情页中的图、Poster、正文和首页 TL;DR 必须对应同一论文，版本差异需记录。保持公开正文中适当的科学条件；首页简述不能比正文声称得更强。

## 4. 图像选择与裁剪模板

固定素材顺序：**完整 Camera-Ready 第一页 → Poster（无则框架/teaser）→ 三张辅助图**。

| 位置 | 默认内容 | 裁剪边界 |
| --- | --- | --- |
| 左侧第一页 | 用户确认或官方最终版本的第 1 页 | 保留完整页面、题目、作者与页内会议信息，不裁成局部图 |
| 右侧上图 | 已有 Poster 优先；缺少时用论文框架图/teaser | 保留整张 Poster；框架图去除外围空白但保留全部模块、箭头、文字 |
| 辅助图 1 | 主要理论/核心对照；理论不适用时选问题或结果图 | 理论使用原文排版截图，保留定理条件、结论、编号及必要假设 |
| 辅助图 2 | 方法图；已有重复时选互补证据 | 不拆掉使方法含义改变的节点、连接或注释 |
| 辅助图 3 | 代表性实验图，优先正文靠前的图 | 保留全部相关面板、坐标轴、刻度、图例、误差线和单位 |

这是稳定的选图原则，不要求每篇论文都有理论或方法图。允许根据论文类型替换为互补的三项内容，并在维护记录说明对应原文位置。Model Collapse 的实验图沿用 **Figure 1**；不能因为后面的图更“好看”而悄悄替换。辅助图不重复用同一张图占位。

裁剪过程统一执行：

1. 先看源图与页面截图，区分**文件自带空白**和**展示框产生的空白**。展示框空白不靠破坏原图解决。
2. 从权威 PDF/原始图导出，按内容外接边界去除多余空白、无关正文和下一条定理的残片，保留约 1%–2% 的短边安全余量。不要机械固定裁掉同样的像素或页边距。
3. 不裁掉必要标题、上下标、脚注、图例或条件。图片说明文字能用 alt 表达时，不把整段图注重复嵌进预览；若图注承载解释数据所必需的条件，则保留或在正文中明确表达。
4. 不重绘、补造、润色或改动学术结果像素，不将缩略图拉伸永久写入源文件。放大图必须能读清原文。
5. 输出 WebP，避免加入白色画布、正方形补边或装饰边框。第一页宽度至少 1200 px，框架/teaser 至少 1000 px，Poster 和辅助图至少 800 px；不靠插值放大低清图片冒充清晰度，优先重新导出。
6. `width` / `height` 填文件真实像素尺寸；双语共用同一图文件，alt 分别本地化。使用稳定路径，不把临时下载或本机绝对路径写进公开元数据。
7. 在本地任务证据中记录源文件/URL、版本、PDF 页码、图表/定理号、裁剪框、导出尺寸及检查结果；公共素材依照 [素材来源登记](../ASSET_PROVENANCE.md) 记录可公开来源。访问 Overleaf 或私稿不等于授权公开整份稿件。

## 5. 固定展示与点击后的内容

以下是已经确定的内容展示约定。日常新增论文沿用组件，不逐篇改 CSS；具体像素值由组件样式管理，避免文档复制一套容易过期的尺寸。

- 桌面采用收窄后的固定上限面板，左侧完整第一页，右侧依次为**完整标题、TL;DR、上图、三张辅助图、Links**。标题不再重复放到左图下面。移动端自然换行和纵向排布。
- **右侧图片铺满内容栏宽度，上图和下方三图总宽度一致，左右边缘对齐。** 不恢复居中窄图组，不保留为了原图比例产生的通栏白边。
- 下方是紧凑横向图行，**不再固定成三个正方形**。桌面预览允许按用户确认的方式拉伸以填满区域；不裁掉科学内容来伪装铺满。左右整列等高，上图使用剩余高度。
- 点击任一预览图，在页内打开对应完整图片；对话框标题为论文完整标题，图片按**原始比例**显示，背景半透明模糊可见。关闭按钮、Escape 和点背景可关闭并返回原位置；保留展开/关闭动画及减少动态效果设置。
- 点击论文标题进入对应语言的详情页；点击 PDF、OpenReview 等资源进入它们的真实目标。不得将图片按钮、内部文章链接和外部资源混为同一种跳转。
- 不添加解释选图过程的可见副标题或图注；alt 用简短的内容描述与必要图号，不只写“图片”“Poster”。

## 6. 资源、索引与 CV

详细卡片和论文页保留全部真实公开资源，使用 canonical `links`；卡片追加确认版本的 PDF 后按 URL 去重。CV 和论文索引是紧凑摘要：有三类可用资源时优先 **OpenReview、arXiv、Code**，无 Code 时用 Publisher。会议主页和同一 arXiv 的 PDF 不作为额外独立资源类型凑数。资源不足时只列实际存在的项。

资源图标沿用共享组件，按目标类型识别；不要在 Markdown 中粘贴图标字符或为每篇论文制作图标。`Code` 在展示时可显示为 `GitHub` / `代码（GitHub）`。英文 `Links:`、中文 `链接：` 独立于会议信息另起一行，链接行允许自然换行。

```markdown
- **Paper #<顺序号>: <完整标题>**。\
  <按确认顺序列作者，保留 * / † 标记>。\
  <会议或已确认的在审状态>。\
  链接：[OpenReview](<真实URL>)、[arXiv](<真实URL>)、[GitHub](<真实URL>)。
```

这是一份待填模板，尖括号占位符不能进入公开页面。英文条目用对应英文标点与 `Links:`，共同一作/通讯作者只在列表前保留一次简短图例。

论文索引的 venue 单元格只放会议、日期、地点；不追加 accepted/poster。只有经核实的 Oral 可放在会议名右侧。在审稿件不能根据投稿模板页眉推断录用会议。同步审查中英文论文页、索引、相关研究页、CV 及可下载 CV 中受影响的事实，不无故改动无关内容。

## 7. 可复用元数据片段

下面是**加入现有完整论文 frontmatter 的片段**，不是替代整个 schema。先补齐 `type/title/name/description/summary/language/tags/authors/status` 等既有字段；新建中文页面使用既有语言配对约定。`reviewed_at` 只在实际复核后填写，`modified/content_hash/review_due` 由维护流程管理。

```yaml
paper_highlight:
  tldr: >-
    <按第 3 节写本语言 TL;DR>
  image: /papers/<paper-id>/overview.webp
  image_alt: <框架图或 teaser 的本语言内容描述>
  width: <真实像素宽度整数>
  height: <真实像素高度整数>
  poster: # 仅当真实 Poster 存在时保留整个块
    image: /papers/<paper-id>/poster-preview.webp
    image_alt: <本语言 Poster 内容描述>
    width: <真实像素宽度整数>
    height: <真实像素高度整数>
  figures: # 恰好三项；顺序见第 4 节
    - image: /papers/<paper-id>/<figure-a>.webp
      image_alt: <内容与原文图表或定理号>
      width: <整数>
      height: <整数>
    - image: /papers/<paper-id>/<figure-b>.webp
      image_alt: <内容与原文图表或定理号>
      width: <整数>
      height: <整数>
    - image: /papers/<paper-id>/<figure-c>.webp
      image_alt: <内容与原文图表或定理号>
      width: <整数>
      height: <整数>
```

已有实现要求框架/teaser 字段始终存在，即使有 Poster。不要添加已移除的 `paper_highlight.image_caption`。链接继续放在论文顶层 `links`，不在 highlight 下另存一份资源列表。首页图使用事件数据里的 `image/width/height/pdf`，不误填成框架图。

## 8. 每次可直接复用的更新指令

```text
依据 docs/content-template.md 更新这项内容：<论文/事件及新事实或素材>。
先复用现有 slug、权威资料和已确认事实，只询问影响正确性的缺项。
沿用固定内容模板和当前组件；不要重新讨论或设计版式。
完成相关中英文论文页面、首页事件、索引/研究关联、CV及资源的必要同步。
TL;DR、正文、关键启示保持同一事实边界；不要编造来源、图像、链接或录用。
按固定选图与裁剪规则准备素材，核对文件真实尺寸及双语 alt；检查预览与放大图。
缺少素材时保留缺项，不用重复图或臆造内容填槽。
交付内容变更、来源/缺项、受影响页面、检查结果；发布遵循项目既有发布规则，
不要把内容输入理解为重新设计模板或自动扩大发布授权。
```

## 9. 内容验收清单

- [ ] 论文身份、作者顺序、姓名、状态、日期和资源在所有受影响页面一致；未知值未被填成事实。
- [ ] 双语 TL;DR 与详情页意义相同，关键启示齐全，重要限制与引用保留。
- [ ] 正确的 Camera-Ready 第一页；Poster 优先或框架回退；三项互补辅助图，来源和图号可追溯。
- [ ] 裁剪无无关页边/正文，不截断标签或假设；无新增补白；元数据尺寸与文件一致。
- [ ] 最新固定布局：右栏收窄但图片铺满，上下等宽，横向辅助图无正方形留白，整列等高；窄屏不溢出。
- [ ] 点击标题进入正确语言详情；图片放大显示原比例、正确标题与完整内容；资源链接真实且去重。
- [ ] CV 链接独立一行，使用共享图标，跨页面资源事实一致。
- [ ] 无占位符、冗余选图说明、临时路径、私稿或未获准公开素材进入公共内容。

自动检查覆盖 schema、像素尺寸、资源完整性及部分几何和交互；不能替代人工核对图像语义、裁剪边界和学术主张。内容改动执行维护流程，页面行为改动执行对应浏览器检查；最终验证与发布统一遵循项目既有发布规则，不要为文档另建发布流程。
